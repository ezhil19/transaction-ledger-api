# API Reference

Base URL: `http://localhost:3000`. Requests and responses use `application/json`. Interactive
docs: `/api/docs`. OpenAPI JSON: `/api/docs-json` (also saved as [openapi.json](openapi.json)).

Money values in responses are 2-decimal strings. Timestamps are ISO 8601 in UTC. All errors share
the format described in the [README](../README.md#error-format).

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/auth/register` | public | Register a user |
| POST | `/auth/login` | public | Get an access token |
| POST | `/accounts` | Bearer | Create an account |
| GET | `/accounts/{accountId}` | Bearer | Get one of your accounts |
| GET | `/accounts/{accountId}/balance` | Bearer | Get the current balance |
| POST | `/accounts/{accountId}/transactions` | Bearer | Add a credit or debit |
| GET | `/accounts/{accountId}/transactions` | Bearer | Transaction history |
| POST | `/transfers` | Bearer | Transfer between accounts (bonus) |

## Authentication

Every endpoint marked **Bearer** needs the header `Authorization: Bearer <access_token>`, using a
token from `POST /auth/login`. Without a valid token it returns **401 `UNAUTHORIZED`**, so 401 is
not repeated in each endpoint's error list below.

Accounts belong to the user who created them. Using another user's account id returns **404
`ACCOUNT_NOT_FOUND`**, the same as an id that doesn't exist.

---

## POST /auth/register

**Body**

| Field | Type | Rules |
|---|---|---|
| `email` | string | required, valid email, max 255. Trimmed and lower-cased. |
| `password` | string | required, 8–128 characters |

```bash
curl -X POST localhost:3000/auth/register -H 'Content-Type: application/json' \
  -d '{"email":"ezhil@example.com","password":"S3cure-pass"}'
```

**201 Created**

```json
{ "id": "01a18300-…", "email": "ezhil@example.com", "created_at": "2026-10-28T10:15:30.123Z" }
```

The password hash is never returned.

**Errors:** 400 `VALIDATION_ERROR`, 409 `EMAIL_ALREADY_REGISTERED`

---

## POST /auth/login

**Body:** `email`, `password`

```bash
TOKEN=$(curl -s -X POST localhost:3000/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"ezhil@example.com","password":"S3cure-pass"}' | jq -r .access_token)
```

**200 OK**

```json
{ "access_token": "eyJhbGciOi…", "token_type": "Bearer", "expires_in": 3600 }
```

**Errors:** 400 `VALIDATION_ERROR`, 401 `INVALID_CREDENTIALS` (same response for an unknown email and
a wrong password)

The examples below assume `TOKEN` is set like this.

## POST /accounts

Creates an account owned by the logged-in user. The balance always starts at `0.00`, and `id` and
`created_at` are generated by the server.

**Body**

| Field | Type | Rules |
|---|---|---|
| `name` | string | required, non-blank after trimming, max 255 |

Any other field (e.g. `balance`) is rejected with 400.

```bash
curl -X POST localhost:3000/accounts -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"name":"Alice"}'
```

**201 Created**

```json
{
  "id": "01a17d9f-5b88-739f-a3e4-582584ca9f9b",
  "name": "Alice",
  "balance": "0.00",
  "created_at": "2026-10-27T13:49:18.126Z"
}
```

**Errors:** 400 `VALIDATION_ERROR`, 400 `INVALID_REQUEST_BODY`

---

## GET /accounts/{accountId}

Returns the account (same shape as above).

**Errors:** 400 `INVALID_ACCOUNT_ID`, 404 `ACCOUNT_NOT_FOUND`

## GET /accounts/{accountId}/balance

```bash
curl localhost:3000/accounts/01a17d9f-5b88-739f-a3e4-582584ca9f9b/balance \
  -H "Authorization: Bearer $TOKEN"
```

**200 OK**

```json
{ "account_id": "01a17d9f-5b88-739f-a3e4-582584ca9f9b", "balance": "100.00" }
```

**Errors:** 400 `INVALID_ACCOUNT_ID`, 404 `ACCOUNT_NOT_FOUND`

## POST /accounts/{accountId}/transactions

Adds a transaction and updates the balance atomically.

**Body**

| Field | Type | Rules |
|---|---|---|
| `type` | `"credit"` or `"debit"` | required |
| `amount` | number | required, > 0, at most 2 decimals, max 9999999999999.99 |
| `reference_id` | string | required, non-blank, max 100, unique per account, case-sensitive |
| `description` | string | optional, max 500 |

```bash
curl -X POST localhost:3000/accounts/$ID/transactions -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"type":"credit","amount":100,"reference_id":"INV-001","description":"Opening deposit"}'
```

**201 Created**

```json
{
  "id": "01a17d9f-6008-725c-97e7-6913901c1bfc",
  "account_id": "01a17d9f-5b88-739f-a3e4-582584ca9f9b",
  "type": "credit",
  "amount": "100.00",
  "description": "Opening deposit",
  "reference_id": "INV-001",
  "balance_after": "100.00",
  "transfer_id": null,
  "created_at": "2026-10-27T13:49:19.242Z"
}
```

**Errors**

| Status | `error` | Example cause |
|---|---|---|
| 400 | `VALIDATION_ERROR` | `type: "refund"`, `amount: 0`, `amount: 1.234`, missing `reference_id` |
| 400 | `INVALID_ACCOUNT_ID` | `/accounts/abc/transactions` |
| 404 | `ACCOUNT_NOT_FOUND` | unknown account |
| 409 | `DUPLICATE_TRANSACTION` | `reference_id` already used on this account |
| 422 | `INSUFFICIENT_BALANCE` | debit larger than the balance |

Example validation error:

```json
{
  "statusCode": 400,
  "error": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "details": [{ "field": "amount", "errors": ["amount must be greater than 0"] }],
  "path": "/accounts/…/transactions",
  "timestamp": "…"
}
```

Example duplicate:

```json
{
  "statusCode": 409,
  "error": "DUPLICATE_TRANSACTION",
  "message": "A transaction with reference_id 'INV-001' already exists for account …",
  "details": {
    "account_id": "…",
    "reference_id": "INV-001",
    "existing_transaction": { "id": "…", "type": "credit", "amount": "100.00", "…": "…" }
  },
  "path": "…",
  "timestamp": "…"
}
```

## GET /accounts/{accountId}/transactions

Returns the account's transactions, latest first by `created_at`.

**Query parameters**

| Param | Default | Rules |
|---|---|---|
| `type` | both types | `credit` or `debit` |
| `page` | 1 | integer ≥ 1 |
| `limit` | 10 | integer, 1–100 |

```bash
curl "localhost:3000/accounts/$ID/transactions?type=debit&page=1&limit=5" \
  -H "Authorization: Bearer $TOKEN"
```

**200 OK**

```json
{
  "data": [
    { "id": "…", "type": "debit", "amount": "20.00", "balance_after": "100.00", "…": "…" }
  ],
  "pagination": { "page": 1, "limit": 5, "total_records": 2, "total_pages": 1 }
}
```

**Errors:** 400 `VALIDATION_ERROR` (bad `page`, `limit` or `type`), 400 `INVALID_ACCOUNT_ID`, 404
`ACCOUNT_NOT_FOUND`

## POST /transfers

Moves money from one of your accounts to any account, yours or another user's. The debit and
credit are written in one database transaction, so a partial transfer can't happen.

**Body**

| Field | Type | Rules |
|---|---|---|
| `from_account_id` | uuid | required, must be one of your accounts |
| `to_account_id` | uuid | required, different from `from_account_id` |
| `amount` | number | required, > 0, at most 2 decimals |
| `reference_id` | string | required. Used as the reference of both legs, so it must be unused on both accounts. |
| `description` | string | optional. Generated if omitted. |

```bash
curl -X POST localhost:3000/transfers -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"from_account_id":"'$A'","to_account_id":"'$B'","amount":30,"reference_id":"TRF-001"}'
```

**201 Created**

```json
{
  "transfer_id": "01a17da0-…",
  "from_account_id": "…A",
  "to_account_id": "…B",
  "amount": "30.00",
  "reference_id": "TRF-001",
  "debit":  { "account_id": "…A", "type": "debit",  "balance_after": "70.00", "transfer_id": "01a17da0-…", "…": "…" },
  "credit": { "account_id": "…B", "type": "credit", "balance_after": "80.00", "transfer_id": "01a17da0-…", "…": "…" }
}
```

If `to_account_id` belongs to another user, `credit` is `null`, because it would show their
balance. Likewise, if a duplicate `reference_id` clashes on their account, the 409 leaves out
`details.existing_transaction`.

**Errors:** 400 `VALIDATION_ERROR` / `INVALID_TRANSFER`, 404 `ACCOUNT_NOT_FOUND` (destination
missing, or source missing or not yours), 409 `DUPLICATE_TRANSACTION`, 422 `INSUFFICIENT_BALANCE`

---

## Not supported, by design

`PUT`, `PATCH` and `DELETE` on transactions return 404 `ROUTE_NOT_FOUND`, because transactions are
immutable. The database also rejects any `UPDATE` or `DELETE` on the `transactions` table with a trigger.
